# 時段行程的直接優先候選

空白時段行程提供並排的「新增優先候選」「新增 ELSE 分支」。前者建立 priority 模式並新增一筆尚未指定巨集的候選，不建立隱藏的任務巨集；後者沿用原分支編輯器。

候選清單與任務巨集的優先候選模式共用 `PriorityCandidatesEditor`。可選任意模式任務巨集、填入引數、查看資格條件摘要、排序、複製及刪除。獨立時段行程編輯器可由摘要按鈕跳至巨集定義；日／周的時段編輯視窗也可直接編輯候選並套用指定。

候選只引用任務巨集，不直接引用一般／內建任務。依順序求值引數與資格條件，第一個符合者執行，後續候選不求值；全部不符合或清單為空時沒有動作。與單獨建立優先候選巨集的執行語意相同。

## 專案資料

原分支模式維持 `branches`，省略 mode 視為 branch。直接候選模式保存：

```json
{
  "display_name": "下午活動",
  "icon": "tabler:calendar-event",
  "mode": "priority",
  "candidates": [
    {
      "id": "候選 UUID",
      "task": { "task_macro_id": "來源巨集 UUID", "arguments": {} }
    }
  ]
}
```

兩種內容互斥，priority 不輸出 branches。空候選清單在資料格式中合法；編輯器刪除最後一個候選時，自動回到空白起始區，再選編輯模式。仍存在但尚未指定任務的候選不會觸發返回。刪除最後一個 ELSE 分支也會回到起始區。任務巨集的空優先候選模式仍保留。複製時段行程會重建行程及各候選 UUID，保留被引用巨集與引數，並配置不重複的 name。

引用、參數改型別／刪除、變數寫入權限與環境匯入重連均涵蓋時段候選。無法刪除被候選引用的巨集，候選 ID 在同一清單中不可重複。

## Runtime 與模擬

Runtime 時段行程保留 `mode: "priority"`，candidates 直接為 `{task_macro_id, arguments}` 呼叫陣列，省略編輯器候選 id 與 task 包裝。project 與 runtime schema 均驗證對應形狀。

單一時段及周序列全天模擬共用同一個候選求值函式。紀錄使用 `/slots/{id}/candidates/{index}/task` 位置，全天執行仍繼承事件優先權及流程控制上下文。時段選取清單的摘要與搜尋也包含候選巨集名稱。
