# 日行程適用用途

日行程可手動複選「主要」「疊加事件」「中斷事件」，表示設計時的預期用途。用途與自由輸入的 `tags` 分開；用途只協助編輯器分群與選取，事件週期仍使用手動標籤計數。

## 資料格式

專案日行程的 `purposes` 為不重複的陣列，值為 `main`、`overlay`、`interrupt`。新建日行程預設為 `["main"]`；省略欄位也視為主要。明確設定 `[]` 表示「未分類」，這是顯示分類，不是儲存的用途值。

複製日行程與建立周內自訂副本會保留用途。新增或移除容器引用、切換事件執行方式、加入預約事件任務，都不會改寫用途。用途存於專案檔，不輸出到 runtime，也不限制實際指派。

## 編輯、清單與篩選

日行程編輯區的「適用用途」提供三個核取方塊，可複選或全部取消。清單預設依「主要 → 疊加事件 → 中斷事件 → 未分類」分組，各組可收合，空群組省略。多用途日行程出現在各個對應群組，但仍是同一個 UUID。

「篩選與檢視」整合搜尋、手動標籤、用途篩選與分組／平面檢視，預設關閉。平面清單每個日行程只顯示一次。搜尋、標籤、用途條件可同時使用；新增、複製與導覽跳轉會解除用途篩選並展開目標群組。

## 選取器

- 周行程與周序列覆蓋的日行程選取器，預設篩選「主要」。
- 事件管理與「預約事件」任務先顯示執行方式，疊加模式預設篩選「疊加事件」，兩種中斷模式預設篩選「中斷事件」。
- 可切換為「全部用途」，選取不同用途或未分類日行程。用途不是指派限制。
- 切換執行方式或篩選不清除既有選取；多選面板跨篩選保留勾選，套用後才提交，取消不修改來源。

## 共用 API 與引用檢查

```js
project.days.uses();                  // 依 UUID 索引的手動用途顯示分類
project.days.uses(dayId);             // { roles: [...] }，找不到回傳 null
project.days.list({ use: 'main' });
project.days.list({ use: 'interrupt', tag: '設備' });
project.days.update(dayId, { purposes: ['overlay', 'interrupt'] });
project.days.references(dayId);       // 實際引用，與適用用途分開
```

`uses()` 的顯示角色包含 `unclassified`。用途不代表是否被使用；刪除確認與引用保護持續依實際周行程、覆蓋、事件與預約任務引用處理。
