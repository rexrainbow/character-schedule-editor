# 數值變數範圍

環境層與應用層的數值變數葉節點可設定選填 `min_value`、`max_value`，作為包含端點的寫入限制。群組、字串、布林與計算式巨集不支援這兩個欄位。

編輯器將「最小值（選填）」「最大值（選填）」並排放於初始值下方。空白表示不限制該方向，儲存時省略欄位；0 是有效限制，不使用 null。使用者模式的環境層定義維持唯讀。

有填入的限制必須為有限數字，最小值不得大於最大值；相等合法，代表固定值。初始值必須位於設定的範圍內；省略初始值時使用既有數值預設 0，同樣檢查範圍。錯誤在欄位區域顯示，阻擋提交與匯入並指出資料位置。編輯器不自動修改初始值來配合新的限制。

專案、環境與執行資料皆保留這兩個欄位；兩層 runtime 變數樹都輸出，包含未被引用的環境變數。複製保留範圍，環境替換採用新環境的限制。變更為字串或布林時，在既有引用檢查及型別變更確認通過後清除範圍。

```json
{
  "display_name": "體力",
  "value_type": "number",
  "initial_value": 95,
  "min_value": 0,
  "max_value": 100
}
```

runtime 應於數值寫入時，先求值並確認結果為有限數字，再截斷至範圍內。此規則適用於設定變數、增加數值與重設初始值，也應套用至 runtime 其他任務的數值寫入。例如 95 增加 10，最後儲存 100；僅設定最小值 0 時，負結果改為 0，正結果不設上限。讀取、一般運算與計算式巨集結果本身不截斷，只有寫入變數才套用。

編輯器模擬依相同方式處理內建數值寫入，後續步驟讀到截斷後的值。發生截斷時，執行紀錄顯示「計算結果 105 → 範圍限制後 100」。測試輸入與重設基準也必須位於設定範圍內；引擎提供的進度變數若違反其範圍，模擬會回報輸入錯誤。外部 engine 任務的副作用仍不模擬。

三份 JSON Schema 限制欄位型別及僅能用於數值變數。最小值與最大值的跨欄位比較、初始值範圍由專案、環境與 runtime 驗證函式補充檢查。
