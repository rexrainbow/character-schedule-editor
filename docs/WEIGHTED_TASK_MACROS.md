# 加權隨機候選任務巨集

任務巨集的 `mode: random` 在呼叫時先篩選資格，再依權重選一個候選。它與 `priority` 的「第一個符合者」不同，不把清單順序當成優先權。

## 執行順序

1. 此巨集先沿用共通的呼叫參數與自身資格檢查；不符合就結束。
2. 依候選清單順序求值所有呼叫參數，再檢查被引用巨集的資格條件。一般任務與內建任務沒有額外資格條件，視為符合；內建任務此階段只求值輸入，不執行副作用或抽取隨機幅度。
3. 完成全部資格檢查後，依清單順序求值符合資格者的權重。不符合者的權重不求值；權重使用目前巨集的參數作用域。
4. 權重必須為有限、非負數；0 不參與抽選。對正權重池抽選一次，只執行選中的動作。抽中的巨集沿用已求值參數與資格結果，不重複檢查。
5. 若池為空，才呼叫選填的後備動作；沒有後備則正常結束。後備動作的參數延至此時求值，後備巨集仍遵守自身資格條件。

參與求值的參數、資格或權重發生錯誤時，停止並回報位置，不將錯誤當成不符合，也不改用後備。符合資格的空巨集仍可被選中；其內容為空時不會轉去後備，因此「有後備」不代表一定有實際任務效果。

## GUI

模式選單新增「加權隨機候選」，頁面上方常駐執行順序。候選卡依序顯示資格摘要、隨機權重及任務／巨集選擇；資格仍屬於被引用的巨集，可由摘要跳轉至其定義。權重共用數字 expression 編輯器，預設 1，可引用變數、計算式巨集或目前巨集參數。當所有資格無限制、權重為合法常數時顯示換算機率；其他情況於模擬顯示實際權重。

支援新增、複製、上下移動及刪除候選，末尾保留新增按鈕。排序不改變權重比例，但會改變固定亂數種子下區間對應的候選。後備動作獨立顯示，可設定或移除，不參與抽選。

## 格式與識別

專案候選為 `{id, weight: NumericOperand, task: Action, description?}`；後備為 `null` 或 `{task: Action, description?}`。權重屬於該候選項目，不寫進被引用的任務／巨集。複製重建候選及巨集參數 UUID，並重連權重與後備內的區域參數。

Runtime data 的候選保留 `{weight, task}`，移除編輯用候選 id／description；後備保留 `{task}` 或 null。變數、參數、任務、巨集及環境重連保護均涵蓋權重與後備。YAML 寫法見 [BLUEPRINT.md](BLUEPRINT.md)。

Runtime Program 的 UUID 與 name 引用模式使用同一套演算法。非空正權重池消耗一次共用 seeded RNG（只有一個候選也會消耗）；空池不消耗抽選亂數。待執行的最小任務保存抽選後的 continuation、呼叫參數及 RNG 狀態；從 pending checkpoint 恢復不會重抽。

模擬器透過 diagnostic 事件顯示資格、實際權重、抽樣值、選中候選或後備原因。摘要／展開一層／全部展開與 Markdown 報告都保留權重和後備的靜態敘述。
