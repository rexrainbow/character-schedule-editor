# 系統能力與執行語意

識別契約已更新：name 為必填持久化符號，取代 engine_key；下文舊 key 敘述以 [NAMING.md](./NAMING.md) 為準。

本文件供人類與 agent 判斷自然語言需求能否由現有功能組合表達。這是既有技術文件的歸納，不新增 runtime 功能，也不是 API 欄位 Schema。相關範例見 [RECIPES.md](./RECIPES.md)。

## 如何判斷需求可行

先將需求拆成「何時發生、狀態從哪裡來、條件如何判斷、執行什麼、狀態如何保存」，再選用構件。

| 需求 | 現有構件 | 注意事項 |
| --- | --- | --- |
| 一周無限循環、開頭周＋工作周 N 次＋結尾周 | 周引用的執行次數 | N 是總次數，無限僅限最後一筆；參見 [周重複](WEEK_REPEAT.md) |
| 每 N 天／每 N 個工作日執行 | 週期事件、計數依據 | 首次為第一個符合日期，不是等待 N 天 |
| 每天一定機率、發生後冷卻 | 機率事件 | 需要 runtime 維護跨日冷卻 |
| 記錄金錢、出勤、體力 | 可寫變數、內建變數任務 | 沒有自動出勤或歷史統計；需明確安排累計 |
| 全勤獎金、未達門檻扣款 | 比較、ALL／ANY、計算式與任務巨集分支 | 門檻、公式與結算位置必須明確 |
| 依體力優先工作，否則休息 | 巨集資格條件、優先候選 | 只選第一個符合者，並非所有符合者 |
| 感冒取代當天工作 | 中斷事件 | 空時段仍會阻擋，不能以留空表示照舊 |
| 檢修正常時恢復原行程 | 中斷事件、專用放行規則 | 在自身時段開始任務之後判斷 |
| 未來某天發生約會 | 預約事件任務 | 僅目前周序列內的未來有效日期 |
| 從數個事件內容選一個 | 固定／加權隨機／依序日行程來源 | 每次實際發生只選一次，整天不變 |
| 移動角色、播放動畫等外部動作 | 環境任務契約 | 編輯器能描述呼叫，實際效果由 engine 提供 |

「資料可表達」不等於「目前模擬器能完整驗證」，也不等於 engine 已實作對應契約。

## 物件與引用

| 物件 | 意義 |
| --- | --- |
| 時段行程 | 可重用活動；包含分支動作或優先候選，也可以只有名稱、沒有任務 |
| 日行程 | 每個時段的活動，加上日開始／結束、時段開始／結束及放行規則 |
| 周行程 | 星期一至星期日的日行程安排，可有周內私有日行程 |
| 周序列 | 有順序的周行程引用、指定星期的 Day Override、有效起訖與事件容器 |
| 事件容器 | 日期規則、日行程來源、執行方式與優先權；不是另一套任務內容 |
| 變數 | 執行狀態；number、string、boolean 葉節點，以群組組織 |
| 計算式巨集 | 依目前狀態求值的數字／布林定義，不是儲存欄位 |
| 任務定義 | Engine 可接受的動作與參數介面，不是動作的 JS 實作 |
| 任務巨集 | 有局部參數與可選資格條件的序列、分支或優先候選 |
| 列舉定義 | 可重用的固定字串選項，不是唯讀狀態變數 |

編輯器連結使用 UUID；`display_name` 供人類閱讀，不能視為唯一識別。`engine_key` 是 engine 契約或對外入口，不能取代編輯器 UUID。圖示與日行程用途屬於編輯資訊。

日行程的手動用途（主要／疊加／中斷）只協助篩選，不限制指派，也不因加入容器自動變更。自訂 `tags` 則會輸出給 runtime，能作為事件日期計數依據。見 [DAY_USES.md](./DAY_USES.md)、[DAY_TAGS.md](./DAY_TAGS.md)。

## 環境、應用與執行實例

- 環境層提供變數、計算式巨集、任務定義、列舉與每日時段數；使用者模式可引用，但不能修改環境定義。
- 應用層提供行程、事件、應用變數、計算式巨集、任務巨集與列舉。
- 環境計算式只能依賴環境定義；應用計算式可依賴兩層。編輯權限與變數的 `read_only` 寫入權限是不同概念。
- 執行中的變數值、冷卻、依序候選進度、預約佇列由 runtime 執行實例維護，不寫回編輯器定義。

完整專案是可編輯存檔；環境檔是可提供或替換的契約；runtime 匯出是給 engine 的定義資料，不能當專案重新匯入。Runtime 保留顯示名稱、去除圖示，環境變數引用轉為 engine key。全部環境變數葉節點與實際使用的環境任務需要有效 key；非空 key 全域重複會阻擋 runtime 匯出。見 [ENVIRONMENT.md](./ENVIRONMENT.md)、[RUNTIME.md](./RUNTIME.md)。

## 日期與當日計畫

1. 周序列引用原周行程；Day Override 先決定當天生效的主要日行程。不存在覆蓋欄位表示繼承，null 表示清空。
2. 開始日是第一周某一天，結束日是最後一周某一天，包含兩端。Day 1 從開始日起算；空序列沒有可執行日期。
3. 每日任務開始前，runtime 決定事件是否發生與本次日行程來源，組成當日計畫。當天任務的設定調整不回溯改變這份計畫。
4. 事件日期固定在周序列位置，不隨主周行程移動。序列有效範圍只裁切執行，不重新設定事件週期相位。

行程進度範本包含目前周次、星期、第幾天、時段、每日時段數、周序列周數。Engine 負責更新；它們不自動提供工作班數或薪資統計。詳見 [ENVIRONMENT_EXPRESSIONS.md](./ENVIRONMENT_EXPRESSIONS.md)。

## 三種事件與計數

| 類型 | 語意 |
| --- | --- |
| 單次 | 只在指定起點發生，不看計數依據 |
| 週期 | 在範圍內第 1、1+N、1+2N… 個符合日期發生，N 至少 1 |
| 機率 | 在符合日期依百分比判定，並受剩餘冷卻限制 |

週期／機率可計數全部日期、指定共用日行程 UUID，或具有指定 tag 的主要日行程。先解析 Override，再判斷資格；不是先按日曆產生週期再過濾。主要日行程為空時只符合「全部日期」；周內私有副本不再等於原具名日 UUID，但可保留並符合 tag。中斷、放行與疊加事件不改變計數資格。

機率冷卻 7 表示發生後跳過接下來 7 個符合日期，第 8 個恢復判定。不符合日期不消耗冷卻。機率 100 仍受日期與冷卻限制。可讀取機率、冷卻設定與剩餘冷卻；調整任務能設定／增加前兩者，不能直接寫剩餘冷卻。當天調整只影響後續日期判定。

事件日行程來源可固定、加權隨機或依序循環。未發生時依序進度不前進；已發生但被其他事件阻擋仍算一次。不同容器引用同一日行程不去重。

詳見 [SEQUENCE_EVENTS.md](./SEQUENCE_EVENTS.md)、[PROBABILITY_EVENTS.md](./PROBABILITY_EVENTS.md)、[EVENT_DAY_SOURCES.md](./EVENT_DAY_SOURCES.md)。

## 日內順序、中斷與放行

全天順序是：日開始 → 每時段的開始／放行／主體／結束 → 日結束。每個階段合併所有來源，並非完整執行一個日行程才換下一個。

來源順序是高優先權事件至 0 → 主要日行程 → 負優先權事件；相同優先權依事件陣列順序。

| 事件執行方式 | 效果 |
| --- | --- |
| 疊加 | 與其他來源一起執行 |
| 中斷主要行程 | 阻擋當前主要日行程，包括 Override 後的來源 |
| 中斷低優先行程 | 阻擋主要日行程與嚴格較低優先權事件 |

房租扣款、薪資結算這類只在日開始／結束執行額外動作、不取代主要時段的需求，使用疊加事件即可。感冒改為看醫生與休息、設備故障改為維修，則使用中斷事件。是否佔滿一天不是分類標準；設備檢修可只中斷部分時段，其餘透過放行恢復原行程。

中斷事件優先權不得為負；同優先權互不阻擋。每時段開始時，依來源順序：

1. 已被阻擋者略過開始任務及放行判斷。
2. 執行未被阻擋來源的開始任務。
3. 中斷事件若有放行規則，於此時求值一次。
4. 放行成立，保留已執行的開始任務效果，略過自身主體與結束，也不阻擋其他來源；否則維持中斷。
5. 全部開始階段完成後，再依序執行主體與結束階段。

未加入放行規則與「已加入無條件放行」不同；空白主體也不代表放行。放行不能解除其他事件的阻擋，下一時段重新判斷。主要日行程與疊加事件忽略放行規則。日開始／結束不受單時段中斷影響。

放行是日行程的專用位置，不能放入一般任務巨集。舊的行程接管／取消行程指令不是現行設計。詳見 [DAY_EVENTS.md](./DAY_EVENTS.md)、[SLOT_RELEASE.md](./SLOT_RELEASE.md)。

## 狀態、條件與任務

- 變數初始值為型別相符的常數，預設為 0、空字串、false。環境初始值是否採用由 engine 決定；重設使用實際初始化基準，不是目前狀態。
- 設定、增加、切換布林、重設只能寫非唯讀葉節點。負增量代表扣除；先前任務的寫入對後續任務立即可見。
- 數值寫入先檢查有限值，再依整數設定朝零截斷，最後套用選填上下限；中間算式不截斷。金錢若設下限 0，就不能靠負值表達債務。
- 增加數值可加隨機幅度；0 不抽亂數。整數目標均勻抽整數偏移，一般數值抽均勻實數。細節見 [RANDOM_INCREMENTS.md](./RANDOM_INCREMENTS.md)。
- 比較、ALL／ANY 可遞迴；ALL／ANY 短路求值。數字支援巢狀四則運算；型別或求值錯誤不是 false。
- 計算式巨集每次依當下狀態求值。分支模式回傳第一個符合結果，只求值選中結果；最後必須有 ELSE，結果型別一致。它不會自動累計歷史。
- 任務巨集先求值引數，再檢查自身資格；不符則略過，呼叫方繼續。序列依序執行；分支選第一個符合者；優先候選選第一個符合資格的巨集，後續候選不求值。
- 選中空巨集仍算選中，不會繼續尋找其他候選。沒有資格條件者永遠符合，可作最後保底。巨集不得直接／間接循環。
- 巨集參數是呼叫作用域的輸入，不是永久變數。引用型參數可指定可寫變數位置；列舉參數限制合法字串。

詳見 [INITIAL_VALUES.md](./INITIAL_VALUES.md)、[BUILTIN_VARIABLE_TASKS.md](./BUILTIN_VARIABLE_TASKS.md)、[VARIABLE_BOUNDS.md](./VARIABLE_BOUNDS.md)、[TASK_MACROS.md](./TASK_MACROS.md)、[COMPUTED_BRANCHES.md](./COMPUTED_BRANCHES.md)、[ENUM_PARAMETERS.md](./ENUM_PARAMETERS.md)。

## 預約未來事件

預約任務建立獨立 runtime 單次事件，不改專案事件定義、不依同名合併。可指定「幾天後」或「幾周後的星期幾」，使用固定／加權候選，沒有依序模式。日期必須晚於今天且在目前周序列有效範圍內；偏移須符合安全整數限制。

到發生日才抽選一次日行程。預約佇列與執行狀態由 runtime 保存；目前沒有取消、改期或防重複任務。完整日期公式與拒絕處理見 [SCHEDULE_EVENT_TASK.md](./SCHEDULE_EVENT_TASK.md)。

## 模擬能驗證的範圍

| 項目 | 現有模擬行為 |
| --- | --- |
| 單一時段 | 條件、巨集與內建變數操作；沒有完整日期或事件上下文 |
| 周序列某日 | Override、日期資格、來源優先權、中斷與放行、全天共用變數 |
| 機率與多候選 | 人工指定是否發生及本次日行程，不推算冷卻歷史或依序進度 |
| 隨機增量 | 可用種子重現，不代表機率事件也由種子抽選 |
| 外部 engine 任務 | 只記錄呼叫，假設不改變變數 |
| 預約事件 | 記錄新預約，不執行未來日期或延續到下次模擬 |

每次從輸入開始，不自動沿用前次結果；明確套用成功數值也不代表連續多日模擬。錯誤停止後續執行，保留部分紀錄，失敗結果不可套用。見 [SIMULATION.md](./SIMULATION.md)。

## Agent 工作流程與限制

1. 找到日期、計數方式、初次執行日、執行位置、公式及所需狀態。
2. 查詢現有物件 UUID 與環境能力，優先重用；缺少薪資公式等業務資訊時先釐清。
3. 選擇 recipe，列出新增物件、引用及外部 engine 假設。
4. 用 MCP `project_commands` 查操作，再查 [PROJECT_API.md](./PROJECT_API.md) 的工作資料格式。存檔 Schema 與命令欄位不能混用；目前部分 values Schema 未完整描述內部欄位，不可猜測。
5. 使用目前 revision 操作；必要時原子批次，確認驗證結果，再明確儲存。遇衝突重新查詢。
6. 以邊界輸入模擬並檢查報告；多日冷卻、薪資累計、預約到期等需 engine 測試，不能用單日成功宣稱已驗證。

系統沒有自動判讀「完成工作」的能力，也沒有通用歷史查詢、真實日期節假日、無限周序列、連續多日模擬或任意程式腳本介面。需要的統計可用可寫變數及明確任務維護；外部完成結果、持久化及時間推進由 engine 提供。不要把結構合法誤認為業務正確。
