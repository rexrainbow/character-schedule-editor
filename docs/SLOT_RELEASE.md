# 中斷事件與放行本時段

事件容器選擇日行程及執行方式；日行程只在各時段開始指派下方提供專用「放行本時段」格。不再提供 `schedule_takeover`、接管範圍或接管對象，也不允許把放行放進一般時段任務或任務巨集。

## 事件執行方式

| execution_mode | 介面名稱 | 預設效果 |
| --- | --- | --- |
| overlay | 疊加事件 | 與其他來源一起執行 |
| interrupt_main | 中斷主要行程 | 每個時段阻擋主要日行程，其他事件保留 |
| interrupt_lower | 中斷低優先行程 | 每個時段阻擋主要日行程及嚴格較低優先權的事件 |

省略時視為 overlay。中斷事件優先權必須為 0 或以上；切換為中斷模式時，GUI 將負優先權調整為 0。同優先權事件不互相阻擋，仍依事件容器原始順序執行。事件管理左欄依優先權顯示，不重排存檔陣列。

即使沒有指定任何時段任務，中斷事件仍預設阻擋；空白不代表放行。主要日行程包含 Day Override 指定的生效來源。

## 每時段執行流程

時段開始階段依優先權處理每個來源，將該來源的開始任務與放行判斷連在一起：

1. 若已被更高優先事件阻擋，略過開始任務與放行判斷。
2. 執行該來源的時段開始任務。
3. 若為中斷事件，求值日行程對應位置的放行條件一次；省略或 null 表示無條件放行。
4. 放行成立：此事件不產生阻擋，略過自身本時段主體與結束任務，保留開始任務已完成的修改。
5. 未設定或條件不成立：維持容器指定的中斷對象，之後處理較低優先來源。

開始階段完成後，依原優先權執行時段主體，再執行時段結束。被阻擋及已放行來源的對應內容略過。下一個時段清空阻擋及放行狀態，重新執行上述判斷。

某事件放行不會解除其他事件產生的阻擋。同一日行程被多個容器引用時，以容器 UUID 區分各次執行。疊加事件及主要日行程忽略放行設定，也不求值其條件。

日開始與日結束位於各時段之外，不設定放行、不受單時段中斷影響。中斷與放行不改變事件週期、計數依據或機率事件候選日期。單一時段行程模擬不包含這些日行程控制；請使用周序列某日模擬。

## GUI 與資料

唯讀畫面（事件預覽、事件日行程檢視器、周行程格子）把放行設定整合到對應的時段主體。空白時段由放行資訊佔滿；有指派時並列顯示指派與放行區，窄欄位上下排列。有條件時顯示「條件式放行」與條件摘要，長條件可停留查看。中斷事件無條件放行且仍有指派時，保留可開啟的指派連結、降低其顯示強度，並警告「此時段行程不會執行」。主要日行程與疊加事件的放行設定顯示為未生效，不套用此警告。這些提示不清除指派、不限制儲存，也不改變執行規則。

日行程預設僅顯示已設定的位置，時段主體即使未指定也會保留。已指定的日開始、日結束、時段開始、時段結束，以及已加入的放行指令，皆依執行順序顯示；收合時各列左側對齊、不縮排，仍可編輯及跳至時段行程。切換按鈕為「顯示全部位置／僅顯示已設定」。顯示全部位置後，每列為：時段開始 → 放行格 → 時段主體 → 時段結束。空格顯示長形新增按鈕，設定後增高顯示名稱與條件摘要。對話框可選擇無條件放行，或以共用條件編輯器設定比較、ALL／ANY、變數與計算式巨集。取消不修改；移除後，僅顯示已設定模式會隱藏該位置。長日行程採變動列高的虛擬清單。

日行程可選 `slot_releases` 陣列，長度必須等於每日時段數。元素 null 表示未設定：

```json
{
  "slot_releases": [
    { "builtin": "release_slot", "condition": null },
    null,
    null
  ]
}
```

條件為遞迴 Condition；沒有任務巨集的區域參數。複製日行程及周內自訂日行程保留設定；條件引用參與刪除、型別變更、事件引用及環境匯入重連檢查。

Runtime 將元素轉成 `{task_key, flow_control: "release_slot", condition}`，存放於相同的日行程欄位。環境變數引用使用 `{type: "environment_reference", name: ...}`。固定內建範本只有 condition 一個參數，可修改 name、display_name、圖示及參數顯示名稱；task_key 的內容為範本的 name。

專案、環境與 runtime Schema 均支援放行規則。Markdown 報告列出容器執行方式，並在日行程各時段開始下方輸出放行規則。
