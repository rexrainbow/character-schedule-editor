# 內建流程控制任務

任務定義清單與使用任務的選單分為「變數操作」「流程控制」「引擎任務」；任務巨集另列。分類由固定範本決定，不存入使用者定義。流程控制範本固定無參數、不能刪除或複製；環境模式可修改圖示、display_name 與 engine_key。

| 專案 builtin | 預設名稱 | 範圍 |
| --- | --- | --- |
| `cancel_lower_priority_slot` | 取消本時段低優先行程 | 從現在起，本時段的剩餘開始／主行程／結束指派 |
| `cancel_lower_priority_day` | 取消本日後續低優先行程 | 從現在起，直到日結束的所有剩餘指派 |
| `cancel_self_day` | 取消本日自身後續行程 | 目前這筆日行程實例的後續指派，包含日結束 |
| `cancel_main_slot` | 取消本時段主要行程 | 主要日行程在本時段剩餘的開始／時段行程／結束指派 |
| `cancel_main_day` | 取消本日後續主要行程 | 主要日行程從現在到日結束的剩餘指派 |

專案任務呼叫為 `{ "builtin": "cancel_lower_priority_slot" }`、`{ "builtin": "cancel_lower_priority_day" }` 或 `{ "builtin": "cancel_self_day" }`，沒有 target、value 或 arguments。時段分支、任務巨集均可使用。

主要行程取消任務同樣使用 `{ "builtin": "cancel_main_slot" }` 或 `{ "builtin": "cancel_main_day" }`，固定無參數。

## 執行語意

只有周序列某日的整體執行器能處理取消。每次命中控制任務，以呼叫來源與目前階段建立取消規則；巨集內繼承呼叫它的事件／主日行程來源。控制任務不終止目前時段行程及巨集的後續步驟。低優先取消任務不取消目前來源；自身取消任務則從下一筆指派開始，取消目前來源本日剩餘內容，包含日結束。

自身以「主要日行程」或「事件組 UUID」識別，而非日行程 UUID。其他事件及主要日行程即使引用相同日行程也不受連帶影響，無論優先權高低。可於檢修事件的日開始判斷：設備異常時取消低優先行程；正常時取消自身後續行程，讓主要日行程繼續。

主要行程取消任務直接指定當天的主要日行程（包含 Day Override 後的主要來源），不比較呼叫者優先權，保留所有疊加事件。高優先事件、低優先事件、主要日行程本身都能呼叫；主要來源呼叫時，目前時段行程與巨集仍完成，僅取消後續指派。已執行的內容不回復。本時段版本於日開始／日結束不生效；本日版本包含日結束。沒有主要日行程時沒有可取消的指派。

其他來源只有優先權嚴格較低才取消，同值即使建立較晚也繼續。順序為正優先權事件、0 優先權事件、主日行程、負優先權事件。因此 0 可以取消主日行程，主日行程可取消負優先權事件；負優先權事件不能取消主日行程。

取消僅影響尚未執行的指派，不回復先前變數修改。被取消的整筆時段指派不再求值任何條件、計算式、引數或巨集。多個控制規則累積作用，符合任一者即略過；同時符合多個規則時，紀錄顯示第一個適用的取消來源。

本時段規則僅套用時段開始／主行程／結束，進入下一時段失效，也不包含日結束事件。於日開始／日結束執行此任務時，記錄未生效提示。本日規則可於日開始使用，涵蓋當天的日結束；下一天清空所有取消規則。每次模擬重新建立規則，不跨執行保留。

單一時段行程模擬記錄呼叫並提示需要周序列某日上下文，不造成失敗、不取消目前巨集步驟。控制未被條件分支選中時，不建立取消規則。

## 模擬紀錄

全天計畫仍列出原本可能執行的來源。實際執行紀錄顯示控制任務是否生效；被取消者標為「已取消，不求值」，另列來源事件／主日行程名稱、控制任務名稱、範圍、發生階段及任務資料位置。可沿用來源日行程與時段行程的跳轉按鈕。

## Runtime 契約

```json
{
  "task_key": "使用者設定的 engine_key",
  "flow_control": "cancel_lower_priority",
  "scope": "slot"
}
```

另一低優先範本為 `scope: "day"`。自身取消輸出 `{ "task_key": "使用者設定的 engine_key", "flow_control": "cancel_self", "scope": "day" }`，僅支援 day 範圍。控制種類與範圍是固定語意，不隨名稱、圖示或 engine_key 改變。engine 必須由周序列執行器處理此指令，使用目前來源實例、優先權及階段；不能將它當成副作用未知的一般任務呼叫。

實際引用的範本仍須有唯一且非空的 engine_key。`environment_requirements.tasks` 列出此 key、顯示名稱與空參數陣列；呼叫本身保留 flow_control 與 scope 供 runtime 辨識。完整專案與環境匯入／匯出保留範本的自訂顯示資訊。project、environment 與 runtime schema 均包含對應結構限制。

主要行程取消輸出 `{ "task_key": "使用者設定的 engine_key", "flow_control": "cancel_main", "scope": "slot" }` 或 `scope: "day"`。runtime 應僅取消主要來源在該範圍內尚未執行的指派，保留所有事件來源；單一時段模擬仍僅記錄缺少周序列某日上下文的提示。
