# 預約下周四約會，依權重選擇結果

## 需求與必要假設

任務執行時，預約目前周序列下一周星期四的單次約會；成功約會日權重 3，失敗約會日權重 1，中斷主要行程。假設目標日期仍在序列有效範圍內。

## 使用的能力與物件

- 兩個共用日行程：成功約會日、失敗約會日；用途手動標為中斷。
- 一個呼叫「預約事件」的時段行程或任務巨集。
- 預約內容：名稱約會、日期模式幾周後的星期幾、offset 1、星期四、加權來源 3:1、interrupt_main、優先權 0。

權重 3:1 表示每次抽選機率 75%／25%，不保證四次恰好三次成功。

## 預期流程

```text
目前周索引 w，執行預約任務
  → 目標為 w+1 周的星期四
  → 建立獨立 runtime 預約，不修改專案事件容器
目標日到來
  → 才抽選成功／失敗日行程
  → 整天使用同一結果，依中斷與放行規則執行
```

「一周後星期四」不等於「七天後」；例如周五執行，前者是下周四，後者是下周五。相同任務再次執行會再建一筆，不會依名稱去重。

## 邊界與驗證

- 使用周序列某日模擬，檢查新增預約的日期、來源權重及模式。
- 目標超過序列結束日、不是未來日或動態偏移不合法時，應記錄拒絕原因、繼續後續任務。
- 單一時段模擬沒有日期背景，不能驗證預約日期。
- 每次模擬從空佇列開始，不會自動跑到約會日；到期抽選與持久化須 runtime 測試。
- 目前無取消、改期、防重複與跨序列預約；不能只靠修改同名專案事件實現它們。

## 操作入口與參考

使用 `days`、`slots` 或 `taskMacros` 建立內容，查詢內建任務範本及其持久化 name。這是任務執行時建立事件，不以 `events.create` 代替未來的動態呼叫；日期、到期選取及重試規則見 [Engine 契約](../ENGINE_SEMANTICS.md)。
