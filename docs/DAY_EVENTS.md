# 日行程事件欄位

日行程新增日開始、日結束，以及每個時段開始、結束事件；各位置可指定一個既有時段行程，預設未指定。事件與主時段行程使用同一套 UUID 引用、選擇器、快速建立、草稿編輯、清空及跳轉操作，不另建事件內容類型。

## 介面

日行程預設收合事件，按鈕顯示「展開事件行程（數量）」與向下箭頭；展開後改為「收合事件行程（數量）」與向上箭頭。日開始／結束以紫色窄列顯示，每時段開始／結束以藍灰色窄列及縮排顯示，主行程維持大卡片。收合時保留總數及各時段事件數量。全部內容共用一個捲動區，長日行程仍只渲染可見時段；周行程的按鈕文字與箭頭採相同行為。

周行程也提供事件顯示切換，可編輯周內自訂日的事件。修改事件引用時遵循既有 Copy-on-Write：僅在指定實際變更時建立匿名日行程，保留來源日的主行程與全部事件；只編輯共用時段行程定義不建立快照。

日行程資訊預覽依執行位置列出已指定的事件與主時段；事件可直接跳至時段行程編輯器。日編輯器內跳轉後返回會還原事件展開狀態及捲動位置。

## 資料

原本 `slot_ids` 不變，每日時段數不包含事件。日行程新增選填欄位：

```json
{
  "day_start_slot_id": null,
  "day_end_slot_id": null,
  "slot_events": [
    { "start_slot_id": null, "end_slot_id": null },
    { "start_slot_id": null, "end_slot_id": null },
    { "start_slot_id": null, "end_slot_id": null }
  ]
}
```

省略欄位代表沒有對應事件。`slot_events` 存在時，長度必須等於 `slot_ids`，每筆具有兩個 UUID 或 null。Schema、引用存在性及長度均在匯入／提交時檢查，錯誤指出實際欄位位置。

複製日行程與私有日快照會獨立複製事件配置，繼續引用原時段行程。刪除時段行程時，引用提示數量包含全部事件位置，確認後清空主時段與事件引用。Day Override 引用的仍是完整日行程，因此事件自然隨之生效。

## Runtime

共用日行程與周內嵌入的私有日行程均輸出上述欄位。預期執行順序為日開始、各時段開始／主行程／結束、日結束；空位置略過，即使主時段未指定，該時段的開始／結束事件仍獨立存在。前一事件的變數更新可供後續內容讀取。

日行程欄位本身不包含週期或優先權，周序列追加日行程的規則另存於 [事件組](./SEQUENCE_EVENTS.md)。[模擬模式](./SIMULATION.md) 可測試單一時段行程，也可選擇周序列某日，按各階段合併主日行程與事件，全天共用變數狀態執行。
