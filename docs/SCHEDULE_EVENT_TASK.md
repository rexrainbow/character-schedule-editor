# 流程控制：預約事件

內建任務 `schedule_event` 可放在一般時段行程、分支或任務巨集內。每次實際執行都建立獨立的 runtime 單次事件，不修改專案的 `event_groups`，也不依事件名稱合併預約。內建任務定義位於「流程控制」，名稱、圖示、engine_key 與固定欄位名稱可由環境編輯模式修改；不能新增或移除固定欄位。

## 設定

- 事件圖示、名稱：名稱留空時使用第一個日行程的名稱。
- 發生日期：幾天後，或幾周後的星期幾。
- 偏移量：共用數字 expression 編輯器，支援數字、變數、計算式巨集、四則運算及任務巨集參數。
- 日行程來源：固定日行程，或隨機權重候選。只允許共用日行程，至少一筆，候選不可重複，權重為正數。沒有依序來源模式。
- 執行方式：疊加、中斷主要行程、中斷低優先行程。
- 優先權：整數，預設 0；中斷模式不可為負數。

來源選取、權重與唯讀檢視沿用事件管理的元件。從此任務打開檢視器時，只能瀏覽，不提供離開草稿的編輯器連結。

## 日期語意

日期使用目前周序列的日位置，不套用事件的計數依據或跳過日期。

- 幾天後：`目前日位置 + offset`，offset 必須為至少 1 的安全整數。
- 幾周後的星期幾：`(目前周索引 + offset) * 7 + 星期索引`，周數至少 0，結果仍必須晚於今天。

例如目前是第一周星期五，1 周後的星期四為第二周星期四；7 天後則為第二周星期五。周數 0 可用於本周尚未到來的日期。

預約只適用於目前周序列的有效執行範圍。非未來日期、動態偏移量不是安全整數或超過序列結束日，會記錄拒絕原因、不加入預約，繼續後續任務。編輯時即可判定的常數錯誤與非法設定會阻擋匯出。

## 專案與 runtime 格式

```json
{
  "builtin": "schedule_event",
  "display_name": "約會",
  "icon": "tabler:heart",
  "date": {
    "mode": "weeks_weekday",
    "offset": { "type": "constant", "value": 1 },
    "weekday": "thu"
  },
  "day_source": {
    "mode": "random",
    "candidates": [
      { "day_schedule_id": "成功約會日 UUID", "weight": 3 },
      { "day_schedule_id": "失敗約會日 UUID", "weight": 1 }
    ]
  },
  "execution_mode": "interrupt_main",
  "priority": 0
}
```

固定來源改用 `day_schedule_id`，與 `day_source` 二擇一。`date.mode = "days"` 時不包含 weekday。一般時段使用數字 operand；任務巨集另支援區域 parameter_reference。

runtime 匯出將 `builtin` 改成 `task_key` 與 `flow_control: "schedule_event"`，移除 icon，保留事件 display_name、日期、來源、執行方式與優先權。環境變數引用會轉換為 engine_key 契約；使用此任務前，環境須為內建任務填入 engine_key。

執行中的預約佇列不屬於專案存檔。Runtime 每次成功預約產生新 UUID，保存目前序列、目標日期、建立位置與來源任務供除錯。到預約日才依權重選一次日行程，整天使用同一個結果；預約當下不抽選。當天再依既有三種執行模式、優先權及「放行本時段」規則運作。同優先權時原有事件在前，預約事件依建立順序排列。此版未加入取消、改期或防重複任務。

## 模擬

「周序列某日」模擬會記錄日期背景，成功預約列在結果中的「新增的預約事件」，同時在 LOG 列出名稱、日期、候選與比例、執行方式及優先權。`result.reservations` 包含預約實例，含 `id`、`sequence_id`、`start`、`target_position`、`created_at` 與 `source_path`。

每次模擬都從空佇列開始，不執行未來日期、不保存到下一次模擬、不寫回專案。一般時段行程模擬缺少目前日期，遇到預約任務會回報日期背景不足；請切換周序列某日模擬。

候選日行程受到引用保護：被預約任務使用時不能刪除。日期 expression 同樣參與變數、計算式巨集及任務巨集參數的引用檢查；巨集複製時會重接參數 UUID。邏輯一覽與 Markdown 報告也顯示預約設定與引用的日行程。

來源選取器依預約執行方式，預設篩選「疊加事件」或「中斷事件」用途，也可改看全部用途。日行程用途由使用者手動維護；預約引用及執行方式變更不會改寫用途，既有來源仍保留。刪除保護依實際引用判斷。
