# 事件容器的日行程來源

日行程來源與事件類型（單次／週期／機率）、執行方式（疊加／中斷主要／中斷低優先）互相獨立。

## 編輯介面

- 固定日行程：沿用單選日行程對話框。
- 候選清單：隨機：多選共用日行程，每筆權重預設 1，可填正數小數；顯示依權重換算的比例。不可為零、負數或非有限數值。
- 候選清單：依序：多選共用日行程，以向上／向下 icon 調整順序。首筆上移與末筆下移停用。

候選不可重複，至少一筆才能套用。選取對話框可搜尋、依標籤篩選；變更篩選不清除已選項目，按套用才更新事件草稿。既有候選維持排序，新選項接在尾端。取消選取或取消事件管理都不提交草稿。

事件管理開啟期間，各來源模式的草稿分開保留。首次切換至候選模式時，固定日行程成為第一筆；首次切換至固定模式時，使用第一筆候選。儲存只輸出目前模式，切換事件類型不改變來源設定。

## Runtime 契約

日行程來源區塊預設收合，標題列保留來源模式，以及固定日行程的圖示／名稱或候選數量。點擊標題展開編輯。來源設定有錯誤時會自動展開，並在標題列顯示警告；收合不修改草稿。隨機候選的權重文字、數值輸入與比例保持同一橫行；手機空間不足時整組換行。

固定來源保留 `day_schedule_id`。多候選來源使用 `day_source`，與 `day_schedule_id` 二擇一：

```json
{
  "day_source": {
    "mode": "random",
    "candidates": [
      { "day_schedule_id": "候選日行程 UUID", "weight": 1 },
      { "day_schedule_id": "另一日行程 UUID", "weight": 3 }
    ]
  }
}
```

依序模式的 `mode` 為 `sequential`，各候選僅含 `day_schedule_id`，以陣列順序為準。專案與 runtime Schema 都涵蓋此結構。

Runtime 應在事件實際發生時選取一次，整天使用同一個日行程。隨機模式依權重選一筆；依序模式每次實際發生前進一筆，最後一筆之後循環。未符合日期、機率未發生或冷卻期間不前進；事件已發生但被其他事件阻擋，仍算一次。依序進度與亂數狀態由 runtime 維護，不寫入編輯器專案。

## 周序列預覽

事件資訊面板第一行顯示事件本身的圖示與名稱，接著顯示間隔／機率、開始與結束日期、優先權與執行方式；規則資訊不再重複事件名稱。

接下來以分隔線區分日行程內容。只有一個日行程時，顯示日行程圖示、名稱與開啟連結，再顯示各時段內容及原有的時段行程連結；固定、隨機、依序來源均採相同行為。事件面板不再於底部重複顯示「開啟日行程」長按鈕。

多於一個候選時，日行程區只顯示第一個日行程圖示與名稱加「...以及更多」，不列出其他候選、不提供日行程連結，也不顯示第一個日行程的時段內容。多日行程並排比較表不在此次功能內。

## 候選日行程檢視

多候選摘要「...以及更多」旁提供「檢視候選日行程」圖示，開啟唯讀對話框並關閉原浮動面板。上方顯示事件圖示、名稱與來源模式。左欄只列出此事件引用的日行程，隨機模式顯示權重與比例，依序模式保留序號；超過八筆提供搜尋，搜尋不變更候選或目前右欄選取。

右欄依執行順序顯示所選日行程，包含日開始／結束、時段開始／結束、放行條件及主要時段。預設只顯示已設定的位置，但保留所有主要時段；可切換顯示全部位置。內容以文字與卡片呈現，不提供修改或指派操作。桌面左右欄各自捲動，手機改成上方橫向候選清單、下方內容；長日行程以虛擬清單顯示。

日行程標題及已指派時段旁的連結可跳至原編輯器；編輯器提供「返回候選日行程」，回到原事件、候選、搜尋與詳情捲動位置。檢視狀態只存在介面中，不寫入專案檔。

事件管理的「日行程來源」標題列右側也提供檢視圖示，來源收合時仍可使用。固定來源會顯示單筆日行程；多候選來源則顯示目前尚未套用的候選順序與權重。未指定有效日行程時，檢視圖示停用。

由事件管理進入時，沿用同一個對話框切換內容，不套用事件草稿。此入口僅提供唯讀瀏覽，隱藏前往日行程與時段行程編輯器的連結。按「返回事件管理」、關閉圖示或 Escape 均先返回原事件管理畫面，保留事件選取、未儲存的欄位、來源展開狀態及左右欄捲動位置；再次取消事件管理才丟棄草稿。

## 單日模擬

輸入區列出當天符合日期規則的事件。機率事件使用「發生」checkbox，預設不發生；單次／週期事件依日期規則發生，不提供此 checkbox。

多個候選時提供「本次日行程」選單，預設第一筆，供使用者自行決定結果。機率事件未勾選發生時，選單停用但保留選擇；單一候選顯示日行程圖示與名稱。依序及隨機來源在單日模擬中皆採手動選擇，不推算前幾天的進度、冷卻或抽選。

執行器先確定各事件的日行程，再套用既有優先權、開始／主體／結束、放行本時段等執行規則。複數候選的選取結果列入 LOG；同一事件的所有時段使用同一結果。明確指定不屬於事件的日行程會回報錯誤，手動設定不能跳過日期規則。設定只存於模擬工作階段，不匯出至專案。

## 引用與刪除

所有候選都參與引用計數、Markdown 報告與 runtime 匯出，但不改寫日行程的手動適用用途。來源選取器依執行方式預設篩選疊加或中斷用途，可切換為全部用途；切換模式或篩選不清除既有選取。刪除共用日行程時，固定來源事件會移除；候選來源會刪除該候選，保留其他候選的順序及權重。最後一筆候選刪除後才移除事件容器。若移除事件會造成任務的事件引用失效，仍沿用既有引用保護。
