## 需求與構件

| 需求 | 現有構件 | 應查的規則 |
| --- | --- | --- |
| 每 N 天／每 N 個工作日執行 | 週期事件與 count | 首次符合日、模板日期範圍、計數與相位 |
| 每日一定機率，發生後冷卻 | 機率事件 | 符合日期、剩餘冷卻與設定變更時機 |
| 記錄金錢、班數、體力 | 可寫變數與內建變數任務 | 初值、提交、整數與上下限 |
| 薪資、全勤獎金、未達門檻扣款 | 計算式巨集、分支及結算任務 | 求值順序、累計與明確重設 |
| 優先工作，否則休息 | 巨集資格與優先候選 | 第一個符合者、空巨集與不回退規則 |
| 在符合資格的活動中依權重擇一 | 加權隨機候選與後備動作 | 先資格、後權重；空池才呼叫後備 |
| 感冒／設備故障取代主要行程 | 中斷事件與放行 | 開始任務、副作用、阻擋範圍與每時段重置 |
| 房租／結算等額外動作 | 疊加事件 | 不需要為了日開始／結束動作使用中斷 |
| 從多個事件日行程選一個 | 固定／加權／依序來源 | 每次發生選一次、被阻擋後的進度 |
| 未來某日發生約會 | 預約事件任務 | 實際未來日期、到期選來源與拒絕 |
| 開頭周＋工作周 N 次＋結尾周 | 周引用的執行次數 | 總次數、日覆蓋、起訖及實際日期 |
| 一周無限循環 | 最後一筆周引用 repeat=null | 跨輪次狀態與有限次 API 推進 |
| 數天／數周的巨觀檢查 | 連續模擬 | 種子、實際抽樣、日終／周末快照與重現 |
| 移動角色、播放動畫等外部動作 | 環境任務定義與 engine handler | 呼叫契約、交易邊界及外部防重複 |

精確規則與測試索引見 [ENGINE_SEMANTICS.md](ENGINE_SEMANTICS.md)。本表不另重述執行順序。

## 定義的角色

- 變數空間：持有永久執行狀態；計算式巨集則依目前狀態回傳數值／布林，不是另一個儲存欄位。
- 任務定義：環境提供的動作介面；任務巨集：應用層的序列、分支、優先候選或加權隨機候選組合。
- 時段行程：可重用活動，也可只有名稱而沒有動作。
- 日行程：主體時段、日開始／結束、時段 hooks 及放行位置。
- 周行程：星期對日行程的安排；周序列：周引用、日覆蓋、重複及事件容器。
- 事件容器：日期規則、候選來源、優先權與 execution；任務內容仍來自日行程。
- 列舉定義：固定字串選項，並非唯讀狀態變數。

環境層提供變數、計算式、任務定義、列舉與每日時段數；應用層可引用環境定義。編輯權限、變數 read_only 與引數存取契約是不同機制。日行程用途屬於編輯分類，tags 則可參與執行。

編輯引用使用 UUID；持久化 `name` 在規定的作用域內唯一，API 可依 UUID 或精確名稱解析。`display_name` 是人類標籤，不能作唯一識別。

## 建議的 Agent 工作流程

1. 拆解「何時發生、輸入狀態、條件、動作、副作用、累計與重設」。不要自行補上未提供的薪資、補發或債務政策。
2. 閱讀本總覽與 Engine 契約，再選用 recipe；確認環境是否提供需要的外部任務。
3. 建立新專案時可用無 UUID 的 YAML 藍圖；編輯既有專案時先讀藍圖總覽，再查精確物件與引用。
4. 使用 MCP `project_commands` 查可用動作及參數。命令工作資料、藍圖與專案存檔是不同形狀，不得混用。
5. 變更使用目前 revision，必要時原子批次；驗證後明確儲存，衝突時重新讀取。
6. 單日檢查分支與邊界；連續模擬檢查週期、冷卻、薪資累計與預約到期。模擬不執行外部 handler，不能證明其真實副作用。

## 能力邊界

系統沒有自動辨識「完成工作」的業務意義、通用歷史查詢語言、真實日期／節假日日曆或任意程式腳本。工作班數、全勤、欠款等統計需用變數與明確任務維護。外部世界效果、持久化策略與補償由宿主 engine 提供。

無限周引用、連續多日模擬、checkpoint 恢復及圖表已存在；不能沿用舊文件中的「尚未支援」結論。功能專題文件若保留演進紀錄，其舊名稱或舊流程不取代 Engine 契約。
