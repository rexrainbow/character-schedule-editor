# 感冒：每天 10% 機率、冷卻七個計數日

## 需求與必要假設

在指定周序列有效範圍內，每天有 10% 機率感冒；發生後接下來 7 個符合日期不再判定，第 8 個恢復。本例只替代發生當天的行程，不表示連續生病七天。

## 使用的能力與物件

- 共用日行程「感冒日」，用途手動標為中斷事件：時段 1 看醫生，後續時段休息。活動可只有名稱；若需要變數效果，再明確指派任務。
- 機率事件「感冒」，固定來源感冒日，機率 10、冷卻 7、計數依據全部日期。
- 起訖使用實際周／星期且涵蓋需求範圍；execution_mode 為 interrupt_main，優先權例如 1。

中斷主要行程會保留其他事件；若要連較低優先事件一起阻擋，改 interrupt_lower。沒有任務的感冒時段仍會中斷，空白不等於恢復工作。

## 預期流程

```text
每天任務開始前：
  符合日期且沒有剩餘冷卻 → 以當時設定判定
  發生 → 選定感冒日，加入當日中斷來源
  後續 7 個符合日期 → 不判定
  第 8 個符合日期 → 恢復判定
```

若計數改成「工作」tag，休假日既不判定也不消耗冷卻。若要多種症狀，可改加權候選來源，每次發生只抽一次，整天沿用。

## 邊界與驗證

- 單日模擬勾選發生：確認主要行程被阻擋、感冒日執行；未勾選則照主要行程。
- 模擬人工決定發生，不用 10% 抽選，也不推算前七天歷史；不能用它證明冷卻正確。
- Runtime 另測機率 0／100、冷卻 0／7及不符合日期不扣冷卻。
- 需要改機率時可用「調整機率事件」；增加 5 是五個百分點。當日計畫不回溯，剩餘冷卻不能直接修改。
- 跨日持續生病需額外狀態及規則，不應把 cooldown 當疾病持續時間。

## 操作入口與參考

使用 `days`、`slots`、`events.create`；先找實際 sequenceId 與 dayId。若任務要引用事件，需取得事件 UUID 且符合當下周序列。
