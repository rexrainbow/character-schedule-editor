# 每七天支付房租 100 元

## 需求與必要假設

以日曆天計，每七天扣 100 元；第一次在 Day 7 的日開始支付，接著 Day 14、21。不是 Day 1 起先付一次。需確認餘額不足是允許負債、截至零，或拒絕付款；本例允許負債。

## 使用的能力與物件

| 物件 | 設定 |
| --- | --- |
| 金錢變數 | 應用層可寫 number，例如初始 1000；不設下限 0 |
| 支付房租巨集 | 序列：增加金錢 -100，隨機幅度 0 |
| 支付房租時段行程 | 單一 ELSE 呼叫上述巨集 |
| 房租日行程 | 僅日開始指定支付房租，其他位置空白；用途手動標為疊加 |
| 房租事件 | periodic、全部日期、間隔 7、起點為 Day 7 的實際周／星期、終點為所需最後日期；overlay、優先權 0 |

事件起點使用固定周序列位置，不存 Day 7 字串。若序列從第一周星期四開始，Day 7 是第二周星期三，不能假設星期日。內建任務使用持久化 name 作為對外名稱。計數與重複周規則以 [Engine 契約](../ENGINE_SEMANTICS.md) 為準。

## 預期流程

```text
Day 1–6：不扣款
Day 7 日開始：金錢 = 金錢 - 100
Day 14 日開始：再次扣款
```

一般週期事件從第一個符合日期就執行。若需求改成「入住先支付」，改從 Day 1 起，每 7 天執行，即 Day 1、8、15。

## 邊界與驗證

- 模擬 Day 6、7、8，確認只有 Day 7 呼叫付款；輸入 1000 後應為 900。
- 以金錢 50 測試負債政策；本例應為 -50。設定 min 0 將變成 0，這不等於完整收取 100。
- 序列不到七天時本例沒有付款日期，不能建立範圍外事件來補足。
- 改變序列開始日不會自動平移事件；若要維持「第七天首次」，需重新計算起點。
- 單日模擬不驗證跨日保存；runtime 另測 Day 7 與 14 累計扣款。

## 操作入口與參考

查詢 `variables`、`taskMacros`、`slots`、`days`、`sequences`；事件使用 `events.create` 並指定 sequenceId。重用現有金錢變數，避免建立第二份餘額。
