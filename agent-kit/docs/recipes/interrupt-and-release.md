# 設備檢修：故障維修，正常放行

## 需求與必要假設

每個時段開始檢查設備，正常時執行原本主要行程，故障時改做維修。本例中斷主要行程，保留其他事件；設備正常為可讀 boolean。

## 使用的能力與物件

| 物件 | 設定 |
| --- | --- |
| 設備狀態變數 | 例如「設備故障」；由檢查任務或 engine 更新 |
| 檢查設備時段行程 | 呼叫環境提供的檢查任務；若環境沒有實作，不能宣稱已能自動檢查 |
| 維修時段行程 | 呼叫維修任務或巨集 |
| 設備檢修日 | 每個時段開始指定檢查；放行規則為「設備故障 == false」；主體維修 |
| 檢修事件 | 按需求單次或週期，interrupt_main，優先權非負 |

## 預期流程

```text
檢修事件.時段 N 開始：檢查設備
檢修事件.放行規則：設備故障 == false
  成立：保留檢查效果，略過自身主體與結束，主要行程可執行
  不成立：阻擋主要行程，執行自身維修主體與結束
下一時段：重新檢查及判斷
```

放行是專用日行程位置，不能做成一般巨集步驟。無條件放行且仍指定維修主體時，該主體永遠不執行。

## 邊界與驗證

- 分別輸入故障 true／false，觀察主體及結束階段的來源。
- 若檢查為外部 engine 任務，模擬只記錄呼叫，不更新故障；測試值須人工設定。
- 若更高優先事件已阻擋檢修來源，檢查與放行都不執行。
- 另一事件仍阻擋主要行程時，本事件放行也不能解除它。
- 維修在主體完成才改成正常，當時段不會重新判斷放行；下一時段才讀到新狀態。
- 日開始／結束仍執行，不在單時段中斷範圍內。

## 操作入口與參考

使用 `variables`、`tasks`、`slots`、`days` 與 `events`。日行程放行配置使用專用資料欄位，從 Project API（專案路徑：`docs/PROJECT_API.md`；未收錄於離線文件包） 查工作格式；不要建立已移除的 takeover 呼叫。
