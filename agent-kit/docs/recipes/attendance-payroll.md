# 出勤累計與每七天薪資結算

## 需求與必要假設

本例每周一至五每天兩班，完整七天為一期，應出勤 10 班。每完成一班工資 100，全勤額外 200，少於 5 班額外扣款 100；恰好 5 班不扣款。第一次結算在 Day 7 日結束，後續每 7 日一次。以上金額與政策是範例，必須由實際需求確認。

假設開始日為周一、每期排班固定、不處理請假扣除應出勤數、超時與部分班次；工作完成一次才計一班。外部任務是否成功由 engine 決定，並不是「排了工作」就自動算出勤。

## 使用的能力與物件

| 物件 | 設定 |
| --- | --- |
| 金錢 | 可寫 number，允許負債與否另訂 |
| 本期完成班數 | 可寫 number、integer_only、初始 0、最小 0 |
| 完成一班巨集 | 代表完成的工作動作後，增加班數 1；可由實際工作流程呼叫 |
| 本期薪資計算式 | number 分支模式，讀取目前班數 |
| 薪資結算巨集 | 先增加金錢「本期薪資」，再重設完成班數至 0 |
| 結算日行程 | 日結束指定結算時段行程；用途為疊加 |
| 結算事件 | periodic、全部日期、起點 Day 7、間隔 7、overlay；日結束排在出勤更新之後 |

計算式：

```text
IF 完成班數 == 10：完成班數 * 100 + 200
ELSE IF 完成班數 < 5：完成班數 * 100 - 100
ELSE：完成班數 * 100
```

這是「按班給薪再加獎扣款」。若需求是固定周薪、未滿半數追回已發工資，公式不同，不能沿用。

## 預期執行流程

```text
每次真正完成一班 → 完成班數 += 1
Day 7 全部工作完成後的日結束：
  金錢 += 本期薪資（此時讀取累計班數）
  重設完成班數（初始值 0）
```

可將結算事件設為負優先權的疊加事件，例如 -1，讓它在主要日行程的日結束之後執行。若其他事件也會更新班數，需確認它們在結算之前；不是選一個負值就自動晚於所有來源。不要先清零再計算，也不要在計算式內期待保存累計值。

## 邊界與驗證

| 結算前班數 | 本期薪資 | 結算後班數 |
| --- | --- | --- |
| 0 | -100 | 0 |
| 4 | 300 | 0 |
| 5 | 500 | 0 |
| 9 | 900 | 0 |
| 10 | 1200 | 0 |

- 用結算日單日模擬，輸入上述班數，檢查金錢變化及重設順序。
- 被中斷的工作主體不會執行其中的累計任務；但若把計數放在全域日結束，就可能錯算。
- 避免同一班重複呼叫完成巨集；沒有自動防重複出勤功能。超過 10 班的政策需另訂，不應靠 max 10 隱藏重複計數。
- 若序列從周四開始或末期不足七天，須決定部分期結算、首個結算日與應出勤數；本例不自動處理。
- Engine 應跨日保存班數及金錢。單日模擬的一般工作任務只記錄呼叫，不能驗證真實完成或整周歷史。
