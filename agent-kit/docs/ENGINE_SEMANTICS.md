# Engine 執行語意契約

本文件是行程定義的統一執行語意，適用於 GUI、藍圖及 engine，不依賴 UUID、畫面操作或特定存檔形狀。`src/runtime/` 是目前的參考實作；模擬器也使用此 runtime。其他 engine 實作應以本文件的結果與順序作為一致性依據。

「必須／不得」描述現行契約；實作對照與測試列在最後。若發現實作與文件不一致，應回報具體輸入及結果，不以猜測補成另一套規則。Schema 合法只代表結構合法，仍需符號、型別、引用、權限及循環驗證。

## 1. 定義、引用與狀態

- `name` 是類型／作用域內唯一的持久化符號，`display_name` 是可重複的顯示文字。精確作用域見 [NAMING.md](NAMING.md)。
- 編輯器用 UUID 維護引用。Runtime Program 可使用 UUID 或 name，但選擇、求值、日期與任務效果必須相同；engine 不應把顯示文字當引用。
- 變數空間存放 number、boolean、string 葉節點；群組不可求值。計算式巨集不是儲存變數，每次引用都依當下狀態求值。
- 定義與執行實例分開。變數值、冷卻、依序候選索引、預約與執行位置不寫回專案或 YAML。
- 日行程 `purposes` 只是編輯分類，不決定中斷行為；事件容器的 `execution` 才決定。日行程 `tags` 則參與事件計數。
- 空時段行程、空任務巨集及空周序列都是合法定義；空周序列沒有可執行日期。空事件日行程仍可能中斷其他來源。

## 2. 條件、計算式與求值

1. `when: null` 是無條件成立；未提供巨集 `eligibility` 等同無資格限制。不存在「遇到求值錯誤就當 false」的規則。
2. ALL／ANY 依陣列順序短路：ALL 遇到 false 停止，ANY 遇到 true 停止；被跳過項目不得求值。空 ALL／ANY 不合法。
3. 四則運算先求左運算元，再求右運算元。比較同樣先左再右，兩側型別必須相同；數字才能使用大小比較，字串與布林僅可相等／不等比較。不做隱式型別轉換。
4. 除零、非有限數字、型別錯誤、缺少引用或參數會停止當前執行，不視為條件不成立，也不改選下一候選。
5. 計算式巨集分支依順序取第一個成立者，只求值選中結果；最後有唯一 ELSE，所有結果須符合宣告型別。
6. 計算式巨集不自行快取、不累計歷史、不寫變數，亦不繼承任務巨集的局部參數作用域。計算／任務巨集循環引用不合法。

例如 `ANY(true, 1 / 0 > 0)` 成立且不除零；`ALL(true, 1 / 0 > 0)` 會錯誤，而非回傳 false。文字語法如何轉成條件樹，見 [BLUEPRINT.md](BLUEPRINT.md)。

## 3. 任務、巨集與優先候選

### 3.1 呼叫與序列

- 進入一般任務／巨集時，先依參數宣告順序求值引數。一般數值、布林、字串與列舉是本次呼叫的輸入值；不在每個內部步驟重新求值。
- 巨集參數只存在於該次呼叫作用域；可轉傳給內層呼叫，不成為永久變數。變數／事件引用參數傳遞的是位置與存取契約，不是其目前值。
- 巨集在引數求值後檢查資格。不成立就略過該次呼叫，父序列仍可繼續下一步。成立後，資格不會在每個步驟重新檢查。
- `mode: sequence` 依步驟陣列逐一執行並等待成功；前一步已提交的變數修改，對後一步的算式／條件可見。
- 環境任務由 handler 實作。handler 回傳值不會自動寫入某個變數，也不會自動使候選選擇繼續往下找。

### 3.2 分支模式

`branches` 依陣列順序檢查，選中第一個成立分支後停止檢查其餘分支。最後的 `when: null` 是 ELSE。

**選中分支不等於保證執行動作。** 例如第一分支成立，但它呼叫的巨集資格不成立，該呼叫會略過；不回頭執行 ELSE。條件成立時選中空巨集也有同樣的停止效果。

### 3.3 優先候選模式

```text
依陣列順序：
  求值此候選巨集的引數
  用這些引數檢查其資格
  不符合 → 下一候選
  符合 → 執行此巨集，整個候選選擇結束
全部不符合 → 不執行動作
```

- 候選只能是任務巨集；所有巨集模式均可成為候選。
- 無資格條件者永遠符合，可作最後保底；它後方的候選不會被檢查。
- **符合資格的空巨集仍然勝出**；內層優先候選沒有選到動作，也不會令外層改選下一候選。
- 被實際檢查候選的引數若有錯誤，立即失敗；不得略過該錯誤後繼續。尚未到達的候選，其引數與資格都不得求值。
- 資格條件不是持續監控機制；候選執行到一半失去資格，不會自動中止或換候選。

## 4. 變數初始值、截斷與寫入

### 4.1 初始化與重設基準

藍圖 `initial` 是原生常數，省略時 number／boolean／string 分別為 0／false／空字串。初始值、數字上下限及整數設定必須事先通過驗證；不合法初始值不會靠截斷自動修正。

參考 runtime 的預設目前值與重設基準均來自 Program 初始值。建構選項 `initialState` 可指定目前值；`initialValues` 另指定**重設基準**，未指定時仍使用 Program 初始值。外部 engine 若採用自己的環境初值，應明確建立目前值與重設基準。

`reset_variable` 使用這個基準，並經一般寫入限制；它不是回到目前測試輸入，也不會重設其他變數。模擬器允許調整測試值，但基準仍是專案初始值。

### 4.2 每次寫入的順序

1. 檢查目標是可寫葉節點、型別正確，數字必須有限。
2. 若 `integer: true`，**朝零截斷**，不是四捨五入或向下取整；負零正規化為零。
3. 套用選填 min／max，將值夾在範圍內。
4. 於該最小任務成功提交時生效；不是等整日或整個巨集結束才套用。

中間算式不自行截斷或夾值。非有限中間結果會失敗，不能靠最後的 max 將 Infinity 修正成合法值。

| 輸入／操作 | 設定 | 結果 |
| --- | --- | --- |
| 寫入 -2.8 | integer=true、無下限 | -2 |
| 寫入 -2.8 | integer=true、min=0 | 0 |
| 8 先增加 5，再增加 -5 | max=10 | 8 → 10 → 5，不是把增量加總後得到 8 |
| 目前值 3，執行重設 | Program initial=8，未另指定重設基準 | 8 |

唯讀值只能由系統進度或明確的宿主系統寫入途徑更新；一般 handler／內建變數任務不得繞過權限。環境層的編輯鎖定與變數 read_only 是不同概念。

### 4.3 隨機增量

增加數值的要求值為 `目前值 + 增加量 + 隨機偏移`，再進行寫入限制。

- 幅度為有限非負數；0 不消耗亂數。
- 非整數目標：偏移為 `[-幅度, 幅度)` 的均勻實數。
- 整數目標：以幅度向下取整作界，均勻選取包含兩端的整數；界為 0 時不消耗亂數。過大而無法安全表示的抽樣範圍會失敗。

## 5. 日期、主要日行程與周重複

- 先解析周引用與星期，再套用 Day Override：沒有覆蓋欄位表示繼承；明確 null 表示清空主要日行程。
- Day 1 是開始日。實際周次仍以周一為周界，因此星期四開始後，下一個星期一是實際第 2 周，但不是 Day 8。
- 每筆周引用的 repeat 是總執行次數；null 是無限，僅允許最後一筆。日覆蓋每一輪都適用，無需複製資料。
- 開始日只裁切第一輪，結束日只裁切最後一輪。無限重複不套用結束日。
- 例如單周執行三次、周四開始／周二結束，執行「周四～周日、完整一周、周一～周二」，共 13 天。
- Runtime `position` 是從第一周周一算起的零基實際日期，`dayIndex` 是相對開始日的零基天數；`templatePosition` 是設定位置。GUI 模板的當日模擬使用該格首次有效出現的位置。
- `runDay`／`nextDay` 每次至多執行一天；有限序列之外的日期拒絕執行。無限序列不是一次呼叫就永遠跑下去。

自動綁定的進度使用實際日期及階段：目前周次、星期、第幾天、時段均為一基；有限 total_weeks 是累計周數，無限時為 0。名稱及完整欄位見 WEEK_REPEAT.md（專案路徑：`docs/WEEK_REPEAT.md`；未收錄於離線文件包）。

## 6. 事件發生、計數與來源選擇

### 6.1 每天開始前建立計畫

每日任務執行前，先解析主要日行程、判斷事件、處理冷卻、選出各事件本次日行程，納入到期預約，最後排序來源。即使之後有日開始任務修改變數或事件設定，**也不回溯重建今天的計畫**。

不同容器選中同一個日行程不去重；它們是不同來源／發生實例。

### 6.2 日期資格與週期

- 單次事件不看 count，只在指定模板位置首次有效到達時發生一次；重複周不令它每輪再發生。若該位置在第一輪開始日前，但之後有有效重複，首次到達可以落在後一輪。
- 週期／機率事件須先符合模板 start～end 範圍，再符合 count。範圍在重複周中仍是模板日期篩選，不是實際總天數。
- count 可為全部日期、指定共用日行程或主要日行程的 tag。先解析 Override，再判斷資格；疊加、中斷及放行不改變資格。
- 空主要日行程只符合全部日期；私有副本不等於原共用日行程，但其 tags 仍可符合。
- 週期在第 1、1+N、1+2N… 個符合日期發生。開始／結束範圍含兩端；序列開始日只裁切執行，不重設已固定的週期相位。重複周的符合日期持續累計，不每輪從零開始。

**每 N 個符合日期不一定等於每 N 個日曆日。** 單周無限重複，事件範圍只設「周日～周日」時，符合日期只有每輪周日；every=1 表示每周日，every=7 則是每七個周日。生活 YAML 採前者。

### 6.3 機率與冷卻

在符合日期：剩餘冷卻大於 0，先減 1 並跳過抽樣；否則依 `random × 100 < probability` 判斷。發生時將剩餘冷卻設為當前 cooldown_days。

因此冷卻 7 表示跳過接下來七個**符合日期**，第八個才恢復抽樣。不符合日期不減冷卻；機率 100 仍受冷卻限制。

調整任務只能 set／increase probability_percent 與 cooldown_days：機率限制於 0～100，冷卻設定限制為非負安全整數。成功提交後，後續 `event(...)` 求值可讀到新設定。修改 cooldown_days 不會回頭改寫 cooldown_remaining；任務也不能直接寫剩餘冷卻。新設定只影響後續判定，不改今天已選結果。

### 6.4 日行程候選

| 來源 | 每次事件發生時的選擇 |
| --- | --- |
| fixed | 使用指定日行程 |
| random | 每個權重須為有限正數；依相對權重選一個，不是百分比總和必須 100 |
| sequential | 從第一項開始，每次發生取下一項，尾端回到第一項 |

未發生事件不抽候選，也不推進依序索引。已發生但後續被中斷，仍算一次選取。選定來源整天不變，不在各時段重新抽選。

### 6.5 亂數與可重現性

參考 runtime 由同一個可保存的 RNG 狀態提供機率事件、加權候選及數值偏移。事件先依定義陣列順序作判定／選來源，接著處理預約；**優先權排序在選擇後才做**，不能用優先權排序取代抽樣順序。

未處於冷卻的符合機率日期，即使機率是 0 或 100，預設判定仍消耗亂數。固定來源不抽亂數；加權來源即使只有一個候選也抽取。任務內的隨機增量在該任務被實際準備執行時抽取。

同一參考實作、Program、初值、種子及操作順序可重現。其他 engine 若要求逐值一致，需使用相同 RNG 與消耗順序（`src/runtime/utils.js`、`src/core/randomValues.js`），不能只聲稱「種子相同」。單日模擬的人工決策覆寫是測試工具特例，詳見第 10 節。

## 7. 日內順序與優先權

```text
day.start
slot 1.start（各來源：開始任務 → 自己的放行判斷）
slot 1.body
slot 1.end
slot 2.start → slot 2.body → slot 2.end
……
day.end
```

**每個階段都依來源順序走一遍**，不是執行完事件 A 的一整天才換 B。來源依以下順序排列：

1. 非負優先權事件，由大至小。
2. 主要日行程，即 Override 解析後的來源。
3. 負優先權事件，由大至小（-1 在 -2 前）。

同優先權保留原順序：宣告事件按事件陣列順序，到期預約接在宣告事件之後並按預約插入順序。優先權 0 的事件仍在主要日行程之前。

例：A、B 都能執行時，`A.slot1.start → B.slot1.start → A.slot1.body → B.slot1.body → A.slot1.end → B.slot1.end`。A 的主體因此可以讀到 B 開始任務已提交的值。

## 8. 中斷與放行

| execution | 當前時段的阻擋對象 |
| --- | --- |
| overlay | 不阻擋其他來源 |
| interrupt_main | 主要日行程 |
| interrupt_lower | 主要日行程，加上嚴格較低優先權的其他事件 |

中斷事件優先權不得為負。同優先權事件互不阻擋。空白主體仍可形成中斷；不能以留空表達「照舊」。

每個來源到達 slot.start 時：

1. 已被較高來源阻擋，則略過自己的開始任務與放行判斷。
2. 否則，完整執行自己的開始時段行程。
3. 若自己是中斷事件且有 release，使用此刻最新變數判斷一次。
4. 放行成立：保留已完成的開始任務效果，略過自己的 body／end，也不建立自己的阻擋。
5. 未加入 release 或條件不成立：建立自己的阻擋，之後 body／end 依規則執行。

所有來源的開始階段走完，才進入主體與結束階段。放行不會解除別人的阻擋；主要日行程及 overlay 的 release 不生效。release 是日行程專用位置，不能當一般巨集動作。

**每次進入下一個 slot.start，清空上一時段的阻擋與放行狀態。** 日開始與日結束不受單時段阻擋影響，來源仍依優先順序執行。沒有隱含的「永久取消本日」狀態。

## 9. 預約、提交、失敗與恢復

### 9.1 預約事件

`schedule_event` 每次成功呼叫建立獨立單次預約，不依同名合併，不修改專案。日期必須晚於今天，並在目前序列的實際有效範圍內：

- days：目前實際 position + offset，offset 至少 1。
- weeks_weekday：以目前周一為基準，加 offset 周再選星期；offset 可為 0，但結果仍必須是未來日期。

日期／加總須為安全整數。無效或超出範圍的預約回報拒絕，不加入佇列；無完整日上下文則失敗。候選在預約到期日才選擇，支援 fixed／random。沒有內建取消、改期或依序預約來源功能。

### 9.2 最小任務是提交邊界

- 最小任務的引數／內建要求值先準備，再保存 pending 任務，之後呼叫 handler 或內建操作。
- 同一最小任務內的變數寫入是暫存交易；自己的後續讀取可見暫存值。成功且 checkpoint 保存成功後，才對後續任務提交，並發送 variable.change／task.completed。
- 失敗、暫停或保存失敗，不提交該任務的暫存寫入。**前面已成功的任務不回滾**，因此整個巨集／一天不是一個大交易。
- 條件／引數準備失敗，保留可重試的原執行位置，不靜默跳過錯誤。
- 外部 handler 已產生的網路、動畫等副作用不能靠變數交易撤回。宿主應使用 invocationId 設計防重複或補償；不能將此機制宣稱為外部效果 exactly-once。

### 9.3 暫停與重試

Checkpoint 保存序列位置、周引用輪次、當日來源、執行堆疊、pending、變數、重設基準、冷卻、依序索引、預約與 RNG。

從 pending 任務恢復時，使用同一 invocationId、增加 attempt，從該最小任務開頭重試；已選分支、引數、亂數及已準備的內建要求值保持不變，不重算前面的資格或分支。已成功完成的早先階段不重播。

重新從藍圖建立新 runtime 是新實例，不等同恢復 checkpoint。Checkpoint 必須對應同一 Program／引用模式；編輯過定義後不能把舊快照任意套上。

## 10. 狀態重置表與模擬特例

| 時點 | 重置／建立 | 保留 |
| --- | --- | --- |
| 新 runtime | 初值／重設基準、冷卻 0、依序索引 0、空預約與日期進度、種子 RNG | Program 定義 |
| 新一天 | 解析今日計畫、階段位置、空阻擋與放行 | 變數、冷卻、候選進度、預約、RNG |
| 新時段開始 | 清空上一時段阻擋及放行 | 其餘執行狀態 |
| 新一周／重複輪次 | 更新日期進度 | 不自動重設任何業務累計 |
| 巨集呼叫 | 建立局部引數作用域 | 永久變數 |
| reset_variable | 僅重設指定目標至基準 | 其他狀態 |
| 恢復 checkpoint | 恢復已保存狀態 | 不是重新初始化 |

因此「每周結算後清空班數」必須明確呼叫重設任務；「新周」本身不會清空。切換序列也不自動重設共用變數，日期進度則依序列分開保存。

- 單時段模擬沒有完整日期／事件上下文。
- 單日模擬從測試輸入建立獨立 runtime，人工指定機率發生與候選，不能代表已累計的冷卻歷史。
- 連續模擬使用同一 runtime 正常跨日抽樣，保存完整日期的外部摘要與快照；取消／失敗當天不列為完整日終結果。
- 模擬器的外部任務只記錄，不執行真正 handler。UI 的天數上限、圖表選取與欄位收合不是 engine 語意。
- diagnostics 開關只控制是否生成並發送細節，不應改變執行結果；runtime 不保存過去診斷歷史。
